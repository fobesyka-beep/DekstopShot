# Проверка DekstopShot 1.0

Актуализировано 3 ноября 2026 года. Ниже указаны реально выполненные проверки и их границы.

## Среда

- Windows 11 x64, сборка 26200; Python 3.12.10 x64; PySide6 6.8.3.
- Два физических монитора 1920 × 1080: основной в (0, 0), второй в (-1920, -106).
- Масштабы Qt / Windows: 100% и 125%. Расположение и системные настройки экранов во время проверки не менялись.
- Прежнее окружение Python 3.15 сохранено в `.venv-python315-backup`; совместимое окружение находится в `.venv`. Локальный Python 3.12 — `.python312`.

## Автоматические проверки

- `python -m ruff check .`: без ошибок.
- `python -m pytest -q`: **40 passed**, без пропусков, включая реальный Win32 ABI.
- Прежний результат Linux 29 passed / 1 skipped относится к переданному архиву, а не к текущему прогону.
- Проверены настройки, миграция прежнего имени, выбор закреплённого монитора, различение окон, конфликт клавиши, кодирование DIB/PNG, владение нативной памятью и очистка GDI.
- Сценарные тесты Qt с подставным API проверяют повторные задания, скрытие своего окна, повтор записи занятого буфера и восстановление интерфейса.

## Реальные проверки Windows

`python main.py --self-test --clipboard` и тот же диагностический режим собранного exe проверяют нативные вызовы без подставного API:

- GDI-захват обоих мониторов в физических пикселях; размеры 1920 × 1080 и отрицательные координаты второго экрана.
- WGC конкретного собственного тестового окна на обоих мониторах: 400 × 300 физических пикселей при 100% и 500 × 375 при 125%. Четыре квадранта имеют ожидаемые RGB; перекрывающее тестовое окно в кадр не попадает.
- Свёрнутое и закрытое тестовое окно отклоняются с понятной ошибкой.
- Регистрация глобального сочетания, реальный конфликт с регистрацией в другом потоке (ошибка 1409), освобождение и повторная регистрация.
- Mutex отклоняет повторное приобретение и освобождается после закрытия дескриптора. Диалог повторного запуска через Explorer отдельно не проверялся.
- Синтетическое изображение опубликовано в системном буфере в CF_DIB и PNG, прочитано обратно побайтно; Qt декодирует правильные цвета и ориентацию.
- Прогон из `dist\DekstopShot\DekstopShot.exe` завершился с кодом 0 и `frozen: true`: подтверждены загрузка нативных зависимостей и WGC через multiprocessing внутри PyInstaller.

Обычный минус был действительно нажат через инструмент управления рабочим столом при работающих исходниках, затем при обычном запуске exe: в обоих случаях после нажатия системный буфер содержал снимок 1920 × 1080. Это отдельная проверка доставки глобальной клавиши, а не имитация WM_HOTKEY в модульном тесте.

Дополнительно `tools/controller_probe.py` прошёл 7 проверок с настоящими Controller, WindowsAPI, Qt, CaptureJob и отдельным тестовым окном:

- системный трей доступен, значок запрошен к показу, минус зарегистрирован;
- окно настроек видимо по Qt и IsWindowVisible; расширенный стиль 0x80080 содержит TOOLWINDOW и не содержит APPWINDOW; реальная область HWND через GetWindowRgn исключает все четыре угла;
- API системного фона вернул успех;
- выбор конкретного окна → скрытие настроек → WGC 400 × 300 → системный буфер с правильными квадрантами → восстановление настроек;
- пауза блокирует снимок и позволяет получить освобождённую клавишу, возобновление регистрирует её снова;
- закрытие скрывает настройки и сохраняет регистрацию, повторное открытие восстанавливает окно;
- параметры реально сохраняются и загружаются из JSON; HWND на диск не попадает.

Этот дополнительный прогон вызывает публичные методы Controller напрямую. Он не подтверждает нажатия всех кнопок мышью или внешний вид значка внутри Explorer.

## Интерфейс и исправления

- GlassShot переименован в DekstopShot: пакет, импорты, окно, трей, журнал, настройки, mutex, иконка, manifest, spec, cmd, workflow и документация.
- При отсутствии новых настроек валидные настройки прежней версии импортируются без изменения старого файла. Новые настройки имеют приоритет.
- Компактный макет 940 × 590: удалены верхний заголовок/статус, весь промоблок с кнопкой снимка и переключатель уведомлений. «Твоя комбинация» заменена на «Горячая клавиша». Уведомления об успешном снимке отключены независимо от старых настроек; ошибки по-прежнему сообщаются.
- Обновлены стеклянные кромки, встречные блики и прозрачная тонировка. Четырёхцветная Gemini сохранена. При 940 × 590 все элементы помещаются без прокрутки; при 800 × 520 ссылки переходят в два ряда и работает вертикальная прокрутка.
- Добавлена нативная маска окна и диалогов, закрывающая прямоугольные углы DWM. Маска проверена после изменения размера и настоящим GetWindowRgn, Acrylic API продолжает возвращать успех.
- На build ≥20348 WGC запрашивается с draw_border=False до первого кадра; на Windows 10 19045 оставлен прежний режим, поскольку API отключения индикатора отсутствует. Четыре регрессионных случая проверяют выбор параметра и отсутствие повтора с рамкой после ошибки borderless-запроса.
- Оба изображения `docs/preview-*.png` заново отрисованы нативным Qt на Windows. Offscreen-плагин этой Windows не обнаруживает шрифты; preview теперь выбирает его автоматически только на других ОС. Это особенность предпросмотра, а не отказ нативного интерфейса.
- Исправлен диагностический вывод JSON для консоли CP1251: символ минуса больше не вызывает UnicodeEncodeError.
- Build_EXE.cmd использует новое имя и выполняет Ruff, pytest, генерацию иконки, сбор лицензий и PyInstaller.

Предпросмотры показывают демонстрационный фон с размытием Qt, а не фактический результат DWM Acrylic.

Попытка отдельно измерить жёлтый индикатор (`tools/border_probe.py`) дала **inconclusive**: GDI не увидел его даже при явном draw_border=True, поэтому отрицательный результат при False не доказывает визуальное отсутствие рамки. Отчёт — `.validation/border-probe.json`. Успешный реальный WGC и передача False подтверждены, визуальная проверка индикатора остаётся отдельно.

## Сборка и воспроизведение

Сборка выполнена через `Build_EXE.cmd`. Результат:

```text
dist\DekstopShot\DekstopShot.exe
```

Для переноса требуется **вся папка `dist\DekstopShot`**, включая `_internal`. Сборка папочная, без установщика и цифровой подписи.

Повторная диагностика из корня проекта, когда обычный DekstopShot закрыт:

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest -q
.\dist\DekstopShot\DekstopShot.exe --self-test --clipboard --output .validation\frozen-smoke.json
```

`--clipboard` заменяет текущий буфер тестовым изображением 2 × 2. Снимки мониторов и окон в диагностике остаются в памяти. JSON-отчёты находятся в `.validation\windows-smoke.json`, `.validation\frozen-smoke.json`, `.validation\controller-smoke.json`. Они описывают отдельные прогоны, а не сертификат для всех Windows-компьютеров.

## Осталось проверить вручную

1. Вставку Ctrl + V в сторонние приложения и AI-чаты. Paint на этой Windows отсутствует; надёжная вставка через доступный инструмент управления другими редакторами не подтверждена.
2. Видимость значка и действия меню в Explorer, отсутствие кнопки на панели задач визуально. Нативные флаги окна и программное скрытие/открытие уже подтверждены.
3. Внешний вид живого Acrylic, блики/hover/нажатия и прозрачность диалогов; Windows 10 и непрозрачный системный запасной вариант.
4. WGC окон Блокнота, браузера, VS Code, аппаратно ускоряемого и защищённого содержимого. Реально проверялось собственное цветовое тестовое окно.
5. Запись сочетания через диалог, физические Ctrl + Alt + S / Num −, удержание клавиши, русскую и английскую раскладки. Регистрация/конфликт/пауза проверены нативными вызовами, обычный минус — реальным нажатием.
6. Отключение закреплённого монитора, смену основного, перестановку экранов и масштабы 150%/200%. Имеющаяся конфигурация 100%/125% проверяется без изменения системных настроек.
7. Перенос полной папки сборки на чистую Windows без установленного Python и проверку на Windows 10 22H2.
8. Визуальное отсутствие жёлтого индикатора при захвате настоящего окна на текущей Windows 11. Проба GDI не смогла наблюдать положительный контроль; наличие вызова API не заменяет эту проверку.
