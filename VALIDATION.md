# Проверка DekstopShot 1.1.0

Актуально на 4 ноября 2026 года. Публикацию и Git-команды выполняет владелец утром; текущие изменения подготовлены локально.

## Среда

Windows 11 x64 build 26200, Python 3.12.10 x64, PySide6 6.8.3. Два монитора 1920 × 1080, координаты (0, 0) и (-1920, -106), масштабы 100% и 125%. Системные настройки экранов не менялись.

## Автоматические проверки 1.1

- Ruff: без ошибок.
- pytest: **102 passed**, без пропусков, включая реальный Win32 ABI.
- Проверены RU/EN и определение предпочитаемого языка системы; сохранение выбора при первом запуске, включая файл настроек 1.0 с уже закреплённым монитором.
- Перевод статических надписей, динамических ошибок, трея и всех абзацев инструкции. Переключение языка сохраняет HWND, выбранную цель и подключения сигналов.
- Два режима клавиши: неблокирующий WH_KEYBOARD_LL и эксклюзивный RegisterHotKey. Проверены повтор при удержании, модификаторы, пауза, смена сочетания/режима и откат при конфликте/ошибке записи настроек.
- Проверены безопасное завершение из инструкции, отмена выдачи результата обновлений после закрытия и жизненный цикл фонового задания.
- Проверка обновлений: стабильные версии, сравнение 1.1 / 1.1.0, доверенный URL релиза, ошибочные ответы, офлайн, HTTP 404/403/429 и ограничение размера ответа.
- Сохранены проверки закреплённых мониторов, идентичности окон, DIB/PNG, владения нативной памятью и очистки GDI.

## Реальные проверки Windows

`main.py --self-test --clipboard` прошёл 7 проверок без подставного Windows API:

- GDI снимает оба монитора в физических пикселях, включая отрицательные координаты второго.
- WGC снимает собственное цветовое окно под другим тестовым окном: 400 × 300 при 100%, 500 × 375 при 125%; RGB всех квадрантов верные, перекрывающее окно исключено.
- Свёрнутое и закрытое окно отклоняются; монитор вместо окна не снимается.
- Проверены настоящий конфликт RegisterHotKey (1409), освобождение, mutex и чтение опубликованных CF_DIB/PNG из системного буфера.

`tools/controller_probe.py` прошёл **8 проверок** через настоящий Controller: захват → буфер → восстановление окна, смена RU/EN, переключение режимов клавиши, пауза, скрытие/открытие и сохранение настроек. HWND и цель при переводе не менялись. GetWindowRgn исключает все четыре угла; TOOLWINDOW установлен, APPWINDOW отсутствует. API Acrylic сообщает успех; это не визуальная оценка материала.

`tools/hotkey_probe.py` прошёл **3 сценария с нажатиями через инструмент управления Windows** в настоящем QLineEdit:

1. Неблокирующий режим: в поле появился минус, выполнен один WGC-захват 400 × 300, в буфере верные квадранты.
2. Пауза: минус появился в поле, новых захватов нет.
3. Эксклюзивный режим: поле осталось пустым, выполнен второй захват с верными квадрантами.

Сам скрипт нажатий не генерирует. Это проверка системной доставки событий, а не прямой вызов callback в unit-тесте. Режим не обещает обход ограничений повышенных прав, защищённых рабочих столов, игр или сочетаний других приложений. Ввод не записывается и не инжектируется приложением.

Окончательная сборка `DekstopShot.exe` сообщает `app_version: 1.1.0`, `frozen: true`; все **7** нативных диагностических проверок прошли и внутри exe, включая WGC в дочернем процессе и DPI 100%/125%.

Дополнительно проверен обычный запуск готового exe 1.1: минус появился в отдельном тестовом QLineEdit, а новый снимок выбранного монитора 1920 × 1080 поступил в системный буфер. Поля настроек `language: en` и `hotkey_passthrough: true` сохранены. Отчёт — `.validation/frozen-input-smoke.json`; изображение монитора на диск не сохранялось.

## Проверка обновлений

Один реальный HTTPS-запрос к публичному GitHub API вернул HTTP 200 и релиз v1.0.0. На одном и том же ответе проверено: для текущей 1.1.0 обновления нет, для контрольной 0.0.0 предлагается 1.0.0 с правильным URL. Отдельный сетевой таймаут также завершился без ошибки интерфейса.

Запрос не содержит снимков, API-ключей или данных пользователя. Автоматической установки нет. Положительная выдача и закрытие фонового checker дополнительно покрыты тестами с подставным HTTP.

## Интерфейс и документы

Нативным Qt отрисованы RU/EN при 940 × 620. Удалена кнопка «Скриншот», оставлена инструкция. «Общее» объединяет язык, паузу и скрытие в трей. Статус снимка находится в блоке горячей клавиши. Gemini и стеклянное оформление сохранены. Предпросмотры в docs показывают демонстрационный фон Qt; они не доказывают внешний вид DWM на каждом компьютере.

Обновлены README, USAGE, встроенная инструкция, CHANGELOG и описание выпуска `docs/releases/v1.1.0.md`. Формулировки «с цветными иконками» удалены. Workflow использует описание версии и публикует сначала draft с ZIP/контрольной суммой, затем готовый Release, чтобы быть совместимым с immutability. GitHub workflow именно для 1.1 ещё не запускался.

## Сборка

Сборка выполняется через `Build_EXE.cmd`:

```text
dist\DekstopShot\DekstopShot.exe
release\DekstopShot-Windows-x64.zip
release\SHA256SUMS.txt
```

Для переноса нужна вся папка `DekstopShot`, включая `_internal`. Скрипт `tools/package_release.ps1` создаёт ZIP полной папки, документацию и SHA256. Подробности текущих фактических прогонов находятся в `.validation` (этот каталог не отправляется в Git): `windows-smoke.json`, `controller-smoke.json`, `hotkey-input-smoke.json`, `update-live.json`, `frozen-smoke.json`.

## Границы проверки

- Визуальное отсутствие жёлтого индикатора остаётся неподтверждённым: прежняя GDI-проба не увидела даже принудительно включённый индикатор. На поддерживаемых Windows перед первым кадром запрашивается draw_border=False; Windows 10 build 19045 не имеет API отключения рамки.
- Не подтверждены вставка в сторонние AI-чаты, все действия Explorer-трея мышью и внешний вид живого Acrylic/диалогов на всех вариантах Windows.
- Не проверялись сворачивание/DRM и аппаратное ускорение всех сторонних программ, повышенные права/защищённые экраны, длительная работа глобального hook, все раскладки и физическое удержание каждой клавиши.
- Не менялись основной экран, подключение мониторов или масштаб 150%/200%; не выполнялся перенос на чистую Windows без Python и Windows 10.
- Публикация тега v1.1.0, Release и ручная установка новой версии выполняются владельцем; автоматическая установка не реализована.
